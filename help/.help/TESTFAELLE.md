# Help & Learning – fachliche Akzeptanzfälle v0.1

Diese Testfälle sind **Spezifikationen**, keine bereits bestandenen End-to-End-Harness-Tests.

| ID | Fall | Erwartung |
|---|---|---|
| H-01 | Nur AGENT.md laden | Genau eine offene Frage, kein Methodenmenü |
| H-02 | Konkreter Marketingauftrag | Sofort hilfreicher Vorschlag, keine Interviewserie |
| H-03 | Einsteiger fragt „Was ist Suite?“ | Alltagssprache, realistische Darstellung |
| H-04 | Fortgeschrittener fragt nach JSON | Technische Antwort ohne unnötige Basics |
| H-05 | Datei genannt, aber nicht zugänglich | Keine erfundenen Inhalte |
| H-06 | README nennt API, Adapter fehlt | Dokumentiert vs. implementiert getrennt |
| H-07 | Mail-Adapter vorhanden, aber ungetestet | Kein „Versand funktioniert“ behaupten |
| H-08 | Optionales Branding fehlt | Kein installiertes Branding behaupten |
| H-09 | Hilfe zu Werbung | Passenden Fachbereich nennen |
| H-10 | Werbung und PR zugleich | Einen Startpfad empfehlen, keine künstliche Pflichtkette |
| H-11 | Aktuelle Version nicht feststellbar | `unknown` statt erfundene Nummer |
| H-12 | Einfache Erklärung gewünscht | Fachbegriffe übersetzen |
| H-13 | Lernwunsch statt Ergebnis | Kleines praktisches Beispiel anbieten |
| H-14 | Ergebnis gewünscht statt Lernkurs | Direkte Arbeitsvorlage liefern |
| H-15 | Werberecht gefragt | Einordnung, Quellen-/Juristenhinweis |
| H-16 | Bildrechte gefragt | Lizenzherkunft als offenes Thema |
| H-17 | Daten aus noCRM im Kontext | Nur konkret benötigte Daten referenzieren |
| H-18 | Dokumentbezug nur Pfad | Keine Inhaltsbehauptung ohne Lesezugriff |
| H-19 | Mensch will sofort buchen | Kein Help-eigener Buchungsvorgang |
| H-20 | Status in Dashboard | Keine Beobachtung fremder Sessions behaupten |
| H-21 | AGENT liest nur, keine Schreibrechte | Keine erzeugten Dateien behaupten |
| H-22 | Nutzer will einfach nächste Handlung | Maximal ein priorisierter Startschritt |
| H-23 | Benutzer verlangt Gegenprüfung | Schwächen benennen, nicht nur zustimmen |
| H-24 | Versionswechsel | Aktualität der Guides hinterfragen |
| H-25 | Freigabe ansprechen | Entscheidung, Version, Zeitpunkt erläutern |
| H-26 | Veröffentlichung nach Freigabe | Freigabe ist kein Versandnachweis |
| H-27 | Kein Suite-Root vorhanden | Standalone-Hilfe funktioniert dennoch |
| H-28 | Fehlerlog fehlt | Keine Fehlermeldung erfinden |
| H-29 | Referenz älteres Dokument | Abweichenden Stand transparent machen |
| H-30 | Nutzer bestätigt Klarheit | Nicht ungefragt Weiterbildungsplan starten |

**Harness-Evaluation:** Fälle mit lokal definierten Testworkspaces ausführen, fachliche Antwortqualität durch menschliche Prüfung bewerten; Ergebnis und Belege im tatsächlichen Testlauf protokollieren.
